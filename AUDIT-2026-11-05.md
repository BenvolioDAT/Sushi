# Sushi engineering audit - November 5, 2026

This audit began with a clean `main` checkout at `4a1f435`. It reviews the
execution architecture, economy and lifecycle decisions, spawning, movement,
workers and logistics, planning, combat, persistence, CPU controls, and seasonal
integration. It includes implemented fixes and automated regression checks.
It is not evidence of successful live gameplay.

Verification labels used throughout:

- **STATICALLY VERIFIED:** traced through source and checked against the stated contract.
- **AUTOMATED TESTED:** exercised in Node with Screeps mocks or static validators.
- **LIVE VALIDATION REQUIRED:** needs actual tick resolution, game objects, and CPU measurements.

## A. Architecture Assessment

### Execution and ownership

`main.loop` conducts a fixed sequence: bootstrap; threat intelligence; economy,
colony and strategic planning; demand generation and spawning; room structures;
creep execution; traffic resolution; cleanup/visuals; and telemetry persistence.
`Tick.Bootstrap` migrates Memory, initializes shared demand state and builds
`HiveMind.Index`. The index supplies a reusable snapshot of creeps, rooms,
structures, hostiles, construction sites and queues.

`spawn.request.manager` calculates local and remote WORK/CARRY shortages,
replacement leads and emergency floors. `Spawn.DemandBoard` joins shared
operation/squad/resource demands. `Spawn.Arbiter`, `Spawn.Policy`, Economy and
Capacity govern admission; `spawn.manager` revalidates and executes the queue.
`Spawn.Intents` accounts for same-tick energy/name use across multiple spawns.
The body builders preserve small affordable recovery bodies and bound larger
bodies by requested capability, energy, movement and replacement deadlines.

Foremen fill the base; Extractors mine local/remote sources; Freighters transport
energy; Techs upgrade; Artificers build and repair. Annex, Pioneer and SupplyRunner
support reservation/expansion. Scouts maintain intelligence. Combat roles and
duo/quad controllers coordinate defense and approved offense. MineralMiner and
ResourceCourier handle ordinary minerals/labs/power logistics; dedicated roles
handle Thorium mining, hauling and Reactor claims.

Energy behavior is coupled through source assignments, source-side haul records,
Freighter reservations, spawn stockpiles and reserve/spending policy. Remote
planning supplies canonical outbound/return lanes and travel estimates.
`Planner.Brain` advances resumable structure-planning jobs; the road planners
use shared geometry and construction-release budgets. Towers, safe-mode policy,
links, labs, terminals, observers and power managers run through room phases.

The request's `Movement.Manager` and `Movement.Verify` module names do not exist
in this checkout. Their relevant responsibilities are implemented by
`utility.Travel.Creep`, `Traveler`, `traffic_manager`, `Tick.Finalize`, remote
route validation and `test/movement-audit.js`.

### Decision systems

The existing separate dimensions are useful and were preserved:

| Dimension | States and responsibility |
| --- | --- |
| Economy | SURVIVAL, RECOVERY, STABLE, SURPLUS; immediate deterioration and sustained improvement confirmation |
| Colony lifecycle | OWNED_NO_SPAWN, BOOTSTRAP, GROWTH, DEVELOPMENT, MATURE; workforce/infrastructure progression |
| Alert | PEACE, THREATENED, SIEGE; danger overlay |
| Operations/squads | Durable task-specific lifecycles and guarded transitions |

Startup prioritizes affordable income and local logistics, then bounded controller
growth and necessary infrastructure. Growth uses reserve and capability signals
instead of just creep counts. Defense retains essential economic work while
gating optional spending. Existing economy and lifecycle hysteresis remain intact;
no competing STARTUP/GROWTH/DEFENSE controller was added.

### Strengths and weaknesses

Strengths include explicit tick order, a shared index and admission path,
per-source capability accounting, conservative economy gates, reusable traffic
ownership, additive Memory migration, diplomacy guards, extensive regression
tests, and feature-detected seasonal support. The graph validator covers 110
reachable production modules with no missing modules or dependency cycles.

The main weaknesses were interactions between durable and current state:
incoming capacity counted as operational capacity, demand values that could only
increase, incomplete job delivery state, and caches or bounded passes with
incorrect scope/fairness. Several large compatibility modules also mix policy,
bookkeeping and legacy helpers, increasing the effort needed to trace an action.
Focused corrections are safer here than replacing the architecture.

## B. Problems Discovered

Every fixed finding below is statically reviewed and covered by the added audit
tests. Severity describes potential consequences; none is a claim of an observed
live incident. Evidence refers to the original code at `4a1f435`, with current
functions retaining the relevant names.

| ID / severity | Affected code and evidence | Consequence and resolution |
| --- | --- | --- |
| F01 / High | `role.Extractor.run`: mining-seat correction returned before `deliverBootstrapEnergy` on subsequent ticks. | Loaded recovery miners could shuttle back to the source before delivering. **Fixed:** a full or continuing emergency delivery runs before seat correction; an empty miner resumes its seat. |
| F02 / High | `HiveMind.Economy.shouldBootstrapSelfDeliver` tested `localCarry + queuedCarry`; `buildSnapshot` included spawning Freighters in active CARRY. | Unavailable haulers could stop the only source-to-spawn delivery path and hide a logistics shortage. **Fixed:** queued/spawning capability remains incoming; only active hauling stops this delivery fallback. |
| F03 / High | `Spawn.DemandBoard.emit` merged a hydrated prior demand with `Math.max` and an emergency OR. | Repeated emissions preserved obsolete population counts, priorities, deadlines and emergency status. **Fixed:** the first emission in a new tick replaces the saved fallback; same-tick emissions still merge. |
| F04 / High | Demand assignment accounting counted all matching queued slots but never reduced excess slots. Existing queued flags survived a demand downgrade. | Reduced demand could still consume spawn energy or retain emergency exemptions. **Fixed:** reconcile living/spawning coverage, retain only needed queued slots, refresh priority/classification, and leave living units alone. |
| F05 / High | `HiveMind.MemoryGC.run` restarted every sweep at the first sorted squad and consumed its work budget on retained entries. | A sufficiently large active squad set could indefinitely starve operations, player, resource and intel cleanup. **Fixed:** a scalar persistent cursor advances across domains and survives Memory deserialization/global reload. |
| F06 / High | `traffic_manager.getPossibleMoves` checked fatigue but did not exclude spawning actors or bodies without active MOVE parts. | Cooperative matching could assume a blocker would vacate when its final directional move could not execute. **Fixed:** these actors retain their occupied tiles. Existing miner locks remain. |
| F07 / Medium | The first traffic candidate bypassed the legality checks applied to fallbacks. | A cached or explicit primary step could repeatedly enter a permanent wall/blocked tile. **Fixed:** check adjacency, terrain and impassable matrix cost, while retaining explicit outward border steps and legal fallback behavior. |
| F08 / Medium | Traffic could push/sidestep an actor without invalidating its positional Traveler/shared-route pointers. | Following directions could be consumed relative to the wrong origin. **Fixed:** accepted deviations clear positional path caches and preserve the one-move-per-tick guard. |
| F09 / High | Final traffic and shared-route matrices wrote road/container costs in the same pass as blocking structures. | A road found after a private hostile rampart could overwrite cost 255. **Fixed:** impassable overlays are written last; a road also retains precedence over a passable container. |
| F10 / Medium | `Traveler.getStructureMatrix` and `getCreepMatrix` used one refresh tick for all rooms. | Refreshing one room could suppress the requested refresh of another already-cached room that tick. **Fixed:** per-room refresh ticks. |
| F11 / Medium | Shared-route selection used `moveOptions.range || 1`. | Explicit range zero became range one, breaking exact-position movement semantics. **Fixed:** default only when range is undefined. |
| F12 / High | Resource jobs exist only for the current tick; ResourceCourier remembered only `resourceJobId`. `Labs.fillJob` emits nothing when its source is empty. | Picking up the final batch could erase the delivery destination next tick and send the inputs back to Storage. **Fixed:** persist a compact delivery receipt with target id/resource until discharge. |
| F13 / Medium | ResourceCourier accepted an existing destination without testing free capacity and retained failed delivery jobs. | Full/invalid destinations could hold cargo in a retry loop. **Fixed:** validate destination capacity/ownership/location, release failed claims and use owned Storage when available. |
| F14 / High | `role.Artificer.repairTarget` returned true for every action result, including failed movement. | Unreachable repairs could retain worker/target claims and preempt useful construction indefinitely. **Fixed:** release failed claims, reuse the short reachability backoff, record the failure, and permit fallback work. Repair approach range is now three. |
| F15 / High | Independent roles were invoked without an exception boundary in `Tick.Creeps.run`. | One role exception skipped later creeps, traffic and final telemetry for that tick. **Fixed:** isolate independent-role errors and retain bounded per-role diagnostics with throttled logs. |
| F16 / Low | Creep dispatch relied on each role to exclude spawning creeps; Tech lacked that guard. | Inconsistent dispatch could issue unusable work/movement and distort diagnostics. **Fixed:** skip spawning creeps before independent-role execution. |
| F17 / Medium | Operation limits used `configuredValue || default`. | An explicit zero discretionary-operation budget silently enabled the default allowance. **Fixed:** finite-value defaults preserve zero. |
| F18 / High | `HiveMind.Operations.run` evaluates at most 25 operations, while emission accepted any saved `strategyDecision === 'allow'`. Hydrated demands also lacked current generic-operation approval checks. | An unevaluated or newly held operation could continue presenting eligible spawn work from an old approval. **Fixed:** require current-tick approval for governed operation emission and demand flushing; synthetic assignment ids without a generic operation remain supported. |
| F19 / Medium | `HiveMind.Strategy.scoreOperations` always took the first sorted `maxCandidates` ids. | Later candidates could never receive updated utility. **Fixed:** rescore the oldest utility samples first with deterministic id ties; honor zero candidate budgets. |

Additional performance finding: repair indexing repeated a structure scan already
performed by `HiveMind.Index`. It now reuses that index and keeps the prior id
array when unchanged.

## C. Improvements Implemented

The changes preserve the current public role/manager interfaces, spawn queue,
traffic ownership, source/remote assignments, economy hysteresis and defense
policy. No new role, strategic state machine or production dependency was added.

The new persistent fields are deliberately small: a GC cursor; an operation's
utility sample tick; a courier's in-flight delivery receipt; one Artificer repair
failure record per creep; and one recent error record per dispatched role.
Movement matrices and their per-room timestamps remain in heap state.

Error diagnostics are available at `Memory.hive.telemetry.creepErrors`. Set
`Memory.config.cpu.telemetry.errorLogInterval` to change the default 100-tick
per-role console throttle. Failure counters are bounded and successful role
execution does not create error records. Artificer repair failures are available
at `creep.memory.artificerRepairFailure`. GC reports expose `sweepPending` and
the persistent cursor for observing progress without per-tick logging.

## D. CPU Optimization

**Measured in mocks:** after the shared tick index was built, repeated repair
index updates required no additional `FIND_STRUCTURES` call. The regression
records exactly one structure scan overall and checks that an unchanged repair
list retains its identity. This is a call-count result, not a CPU percentage.

**Expected benefits, not measured live:** failed repairs back off for the existing
short reachability TTL; stale demand no longer funds excess queued bodies;
blocked traffic steps no longer execute impossible directional moves; and
positional paths rebuild after deviations rather than repeatedly following the
wrong origin. Strategy rescoring keeps its configured candidate bound while
eventually visiting later ids.

Correctness has some necessary costs: demand reconciliation updates retained
requests, room refreshes are no longer incorrectly suppressed, and traffic
deviations may cause another path search. GC bounds examined records by its
configured work budget; key enumeration/sorting is still proportional to the
relevant Memory collections, so that budget is not a strict CPU-time ceiling.
No live CPU, bucket, travel-time or population-efficiency result is claimed.

The final audit suite contains **24 cases**, covering multi-tick miner delivery,
incoming hauling, demand reductions, stale emergency classifications, GC fairness
and reloads, immobile blockers, blocked tiles, path invalidation, rampart/road
overlays, exact range zero, border-step preservation, per-room Traveler caches,

spawn dispatch, shared repair scanning, zero budgets, stale approvals and fair
utility sampling. It is included in both `npm test` and `npm run validate`, and
is separately available as `npm run test:audit`.

An existing remote bootstrap test was corrected to give its actor an active MOVE
part before expecting an explicit directional move. Stationary-miner protection
is still asserted in that test. This reflects the documented movement contract:
directional movement requires MOVE, with separate API semantics for being pulled.
[Screeps Creep API](https://docs.screeps.com/api/#Creep.move).

**Final result:** `npm run validate` exited successfully. All 36 validation
scripts passed, including all 24 audit cases, 55 Season 11 cases and 22 Season 11
plus power pipeline cases. The graph check found 110 resolved/reachable modules
and zero cycles. The movement ownership check passed. `git diff --check` passed.
The pipeline includes syntax/load and main-loop smoke checks, the dependency graph, movement
ownership, economy/lifecycle/body/spawn/Memory tests, remote routing and bootstrap,
combat/diplomacy/squads, resources, and Season 11/power regressions.

Mocks do not reproduce the complete engine, pathfinder, simultaneous intent
resolution, account/server state, or actual CPU charging. The deferred-action
tests deliberately apply inventory changes between simulated ticks, but do not
turn mock success into live validation.

## F. Screeps Live Testing Plan

Deploy or confirm that the local Screeps client has synced the complete updated
working tree. No live game was accessed during this audit. Existing watch/sync
configuration may upload saved files independently of Git operations.

1. **Ordinary operation, 300-500 ticks:** confirm harvesting, base filling,
   upgrading, construction and normal remote deliveries continue. Watch state
   transitions for sustained recovery and immediate deterioration; a pending
   replacement must not appear as active hauling.
2. **Recovery in a test room or an existing collapse:** a full local miner with
   no active hauler should complete the trip to a spawn/extension, then return to
   its station. Merely queueing a Freighter must not stop that trip. Observe at
   least one delivery round trip and the first active local hauler.
3. **Changing demand:** when a defense/operation requirement naturally shrinks,
   check that excess queued slots disappear and the retained requests lose old
   emergency priority. Existing living units should remain intact. A held generic
   operation should not retain eligible board requests from a past approval.
4. **Movement:** observe a crowded source lane and one inter-room round trip.
   Check swaps/chains, loaded-hauler precedence, immobile blockers, miner seats,
   border entry/exit and safe fallback tiles. A sidestepped actor should rejoin
   useful travel rather than walk a stale offset path.
5. **Workers/couriers:** observe one lab or power delivery that exhausts its
   source, plus a destination that becomes full or disappears. Confirm cargo is
   delivered or safely deposited. An unreachable repair should release its claim
   and permit useful work instead of monopolizing the worker.
6. **Persistence/CPU:** inspect GC over enough scheduled runs to complete a sweep;
   its cursor should advance while protected records remain. Compare the existing
   rolling CPU telemetry and bucket across similar workloads before and after
   deployment. Use those observations for any tuning decisions.

For a spawn/recovery problem, share only the affected room's RCL, available and
capacity energy, role population, `Memory.rooms[roomName].economy.state` and
reason, colony state, and `Memory.rooms[roomName].spawn.lastDecision`. For the
miner loop, also share the miner's current position, source id and
`extractorState` over several ticks.

For a worker issue, share that creep's task/target ids and recent repair failure
or courier delivery receipt. For a role exception, share the corresponding
`Memory.hive.telemetry.creepErrors` entry and its throttled console stack. For
movement trouble, share the creep/room names, source or destination, several
tick positions and any relevant route traffic diagnostics. For CPU trouble,
share `require('HiveMind.Telemetry').getView()` and
`Memory.hive.telemetry.cpu` with the bucket trend.

## G. Remaining Opportunities

- **Link construction and same-tick receiving capacity:** `Resource.Links.classify`
  selects nearest links without a distance bound, and multiple sources select
  receivers using the same pre-resolution store snapshot. Add staged-construction
  and deferred-intent tests before changing classification or routing policy.
- **Squad pulling:** `Squad.Quad.tryPull` issues `pull` and then ordinary wrapper
  movement for the fatigued member. The wrapper/traffic path does not implement
  the API's `move(pullingCreep)` overload. Actual pulling therefore requires a
  separate tested movement contract and engine validation; it is not established
  by the existing directional-move tests.
- **Wider fault boundaries:** the new protection covers independent roles.
  Squad execution, room managers and strategic phases can still abort a tick if
  they throw. Add subsystem-specific fault injection before deciding which partial
  failures can safely continue; CPU termination is not handled by a JavaScript catch.
- **Large-empire CPU and Memory:** profile shared-route serialization, index and
  queue scans, matrix-signature sorting, visual work, GC key enumeration and the
  large planning modules. Existing cadence/budget controls are useful, but mock
  tests cannot determine the best live settings.
- **Resource and seasonal accounting:** link, terminal, power and Reactor intents
  deserve engine-backed simultaneous-action scenarios. Existing delivery counters
  and throughput estimates should not be treated as measured resolved income
  without checking the following tick's state.
- **Architecture cleanup:** the module graph reports no orphans. Extract helpers
  from the largest modules only when tests and a concrete maintenance benefit
  justify it; this audit did not delete reachable systems or replace working policy.
